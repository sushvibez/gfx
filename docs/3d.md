# 3D

The 3D path lives in `render` (the renderer, materials, model loading,
animation, picking), `scene` (the node tree over ECS columns) and
`physics/p3` (queries, a character controller and rigid dynamics), with
`ui.Viewport3D` embedding a 3D view inside the 2D toolkit. DESIGN.md §9 is
the design document; its *Status* notes are the authority on what is built.
This page describes the current code.

## Renderer3D

`render.Renderer3D` is a forward renderer of indexed meshes: depth-tested,
back-face culled, Cook-Torrance PBR (metallic/roughness), one directional
light with a 2048 px PCF-sampled shadow map, and per-draw data in an
instance-indexed storage buffer. A frame records two passes: a depth-only
shadow pass from the light, then the lit main pass that samples it.

```go
r, err := render.New3D(device, queue, format)   // format: the target's texture format
r.SetShadowArea(core.V3(0, 0, 0), 6)            // everything within 6 units of the origin casts and receives shadows
depth := device.CreateDepthTexture(w, h)
depthView := depth.CreateView()

// per frame
vp, eye := cam.ViewProj(w, h)                    // core.Mat4 view-projection and the camera position
r.Begin(vp, lightDir, eye)
r.Draw(r.CubeMesh(), core.Mat4Scale(core.V3(16, 0.1, 16)), render.RGBA{R: 0.4, G: 0.42, B: 0.47, A: 1})
r.DrawPBR(cube, model, render.RGBA{R: 0.85, G: 0.85, B: 0.9, A: 1}, 0.9, 0.25, nil)   // metallic, roughness, texture
enc := device.CreateCommandEncoder()
if err := r.Render(enc, view, depthView, gpu.Color{R: 0.04, G: 0.045, B: 0.07, A: 1}); err != nil { ... }
queue.Submit(enc.Finish())
```

`examples/cubes` is this loop with a scene-tree hierarchy of spinning
cubes; `go run ./cubes -screenshot out.png` renders one frame headlessly
(`RequestAdapter(nil)`, `CreateRenderTexture`, `ReadTexture`).

Meshes:

| Call | Meaning |
|------|---------|
| `NewMesh(verts []Vertex3D, indices []uint32)` | upload indexed geometry; derives a tangent frame from the UVs when `Tan` is zero |
| `CubeMesh()`, `SphereMesh()`, `CylinderMesh()`, `ConeMesh()`, `PlaneMesh()` | cached unit primitives owned by the renderer |
| `NewLines(verts, indices)`, `NewSegments(pts)` | line meshes for `DrawLines` (1 px, unlit, never picked, no shadow) |
| `Mesh.Bounds()`, `Mesh.Stats()`, `Mesh.Release()` | model-space AABB; vertex and triangle counts |

`Vertex3D` is `{Pos, Normal core.Vec3; U, V float32; Tan core.Vec4}`; the
tangent's `w` is the handedness.

Draw calls are queued between `Begin` and `Render`. The legacy family
takes a colour and a few scalars:

| Call | Look |
|------|------|
| `Draw(mesh, model, color)` | non-metallic, roughness 0.6 |
| `DrawTextured(mesh, model, color, img)` | the same with a base-colour `*Image3D` (nil = plain) |
| `DrawPBR(mesh, model, color, metallic, roughness, img)` | full parameters |
| `DrawUnlit(mesh, model, color)` | flat colour, no lighting (grids, gizmos) |
| `DrawLambert(mesh, model, color, ambient, shadows)` | diffuse only, display space, no tone map (QtQuick3D DefaultMaterial) |
| `DrawShaded(mesh, model, color, ambient, img)` | PBR lifted by a strong ambient term (a part-viewer look) |
| `DrawLines(mesh, model, color)` | line meshes |

`NewImage3D(w, h, rgba)` uploads a texture for these;
`NewImage3DMipmapped` builds a full CPU box-filtered mip chain and is what
materials want. The legacy shader discards texels whose texture alpha is
near zero (hair cards, leaves) rather than blending them.

## Materials and lights

The second pipeline family takes a `render.Material` and is where the
environment model lives: `DrawMaterial(mesh, model, *Material)` and
`DrawInstanced(mesh, []core.Mat4, *Material)` — the latter is one
instanced draw call for every transform in the slice, the path for
foliage and debris. Every numeric field treats its zero value as the
default, so `&render.Material{Albedo: img}` is a white, opaque,
unit-scaled surface.

| Field | Meaning |
|-------|---------|
| `Albedo`, `Normal`, `ARM`, `RoughnessMap`, `Emissive` | the texture set a Poly Haven or glTF asset ships: sRGB base colour, tangent-space normal map (OpenGL +Y), packed occlusion/roughness/metallic, or a standalone grayscale roughness with `RoughnessChannel`, and sRGB emission |
| `Color`, `Metallic`, `Roughness`, `NormalScale`, `UVScale`, `Emission` | scalar factors multiplied with the maps |
| `Triplanar` | world-space projection on the three axis planes blended by the normal — no UVs needed, no stretching on cliffs |
| `AntiTile`, `AntiTileRotation` | stochastic hex tiling (three hex-lattice samples with per-cell offset and rotation, variance-preserving blend) that removes the repeating grid of a tiled texture; the rotation scale keeps brick courses readable |
| `Unlit`, `DoubleSided`, `Alpha` | skip lighting; draw back faces with flipped normals; `Alpha < 1` takes the blended pipeline variant and is drawn after the opaques, sorted back to front |

Materials cache their bind groups per pipeline variant; `Material.Release`
frees those, never the textures.

```go
wall := &render.Material{Albedo: brickA, Normal: brickN, ARM: brickR, UVScale: 2.5, NormalScale: 1.4,
    AntiTile: true, AntiTileRotation: 0.04}
blocks := &render.Material{Albedo: stoneA, Normal: stoneN, ARM: stoneR, UVScale: 0.7, Triplanar: true, AntiTile: true}
r.DrawMaterial(wallMesh, core.Mat4Translate(core.V3(0, 3, -7)), wall)
r.DrawInstanced(r.CubeMesh(), blockTransforms, blocks)   // one draw call
```

Lighting: the directional light and its shadow map come from `Begin`;
`SetPointLights([]PointLight)` and `SetSpotLights([]SpotLight)` add up to
16 shadowless local lights per frame, with Godot-style windowed range
attenuation and a smoothstep cone (`PointLight{Pos, Color, Energy,
Range}`, `SpotLight` adds `Dir`, `Angle`, `AngleAttenuation`).
`SetFrameSettings(FrameSettings)` carries the frame-wide look — `Ambient`,
`Exposure`, `Tonemap` (0 none, 1 filmic, 2 ACES), exponential height fog
with aerial perspective toward a `SkyTop`/`SkyHorizon` gradient — and
`DefaultFrameSettings()` is the neutral starting point. These apply to
material draws only; the legacy `Draw*` family does not see them. The
pass is LDR (tone mapping happens at the end of the fragment shader) and
there is no IBL, no clustered light culling and no shadows from local
lights.

`examples/materials` is the diptych: a brick wall and stone floor tiled
plainly on the left and hex-tiled on the right, under three coloured point
lights and fog, with an instanced row of triplanar blocks. It reads the
Poly Haven sets from `build/textures` (`GFX_TEXTURES` overrides) that
`scripts/fetch-assets.sh` downloads.

## The render graph (v0)

`render.Graph` is the render graph from DESIGN.md §9 in its first form:
passes declare the transient textures they write and read, the graph
culls passes that never reach the presented target, orders writers before
readers, pools transient textures across frames and records everything
into one submission.

```go
g := render.NewGraph(device, queue)
scene := g.Texture("scene", w, h)                       // transient RGBA8 target
g.Pass("scene", scene, clear, func(p *gpu.RenderPass) { ... })
g.PassToTarget("final", clear, func(p *gpu.RenderPass) { ... }, scene)   // reads scene, writes the presented view
err := g.Execute(surfaceView)                           // culls, orders, allocates, records, submits, resets
```

Only RGBA8 transients and colour-only render passes exist so far;
`GraphTexture.Texture()`/`View()` are valid inside a pass callback, and GPU
objects a callback records must live until `Execute` returns.
`Renderer3D` and the 2D UI record directly into a command encoder and do
not go through the graph yet.

## Models: glTF

`render/gltf` parses `.glb` and `.gltf` into a `gltf.Document` of plain
Go values — meshes with primitives (positions, normals, UVs, tangents,
joints, weights, indices), materials, a node hierarchy with the default
scene's roots, skins and animations. `Parse(data, resolve)` takes a
callback that fetches external `.bin` and image files by URI; pass nil for
a self-contained `.glb`.

```go
data, _ := os.ReadFile(path)
doc, err := gltf.Parse(data, func(uri string) ([]byte, error) {
    return os.ReadFile(filepath.Join(filepath.Dir(path), uri))
})
model, err := r.BuildModel(doc)
model.Draw(r, core.Mat4Identity())
```

What the loader keeps from a material: base-colour factor and texture,
metallic and roughness factors, the normal map and `NormalScale`, the
metallic-roughness and occlusion images (`BuildModel` packs them into one
ARM map), emissive image and factor, `DoubleSided`, `AlphaMode`
(`OPAQUE`, `MASK` or `BLEND`) with `AlphaCutoff`, and `Extras`. A material
with `BLEND` draws through the blended pipeline variant; `MASK` is
recorded but the renderer applies its texture-alpha cutout regardless of
the mode and does not use the cutoff value. `KHR_materials_pbrSpecularGlossiness`
diffuse stands in for base colour on older exports; other extensions are
ignored. `Extras` are kept verbatim as `json.RawMessage` on the document,
the default scene, meshes, materials and nodes — Blender custom properties
arrive here.

`render.Model` is the document turned into GPU resources, one draw item
per primitive, with the node hierarchy retained so a pose can be rewritten:

| Call | Meaning |
|------|---------|
| `Draw(r, transform)`, `DrawTinted(r, transform, tint)`, `DrawFaded(r, transform, alpha)` | the whole model; tint multiplies every material colour; fade is real alpha through the blended pipeline (a CPU triangle dissolve when CPU skinning is forced) |
| `Primitives() []ModelPrimitive` | each piece's mesh, local transform, resolved material values and maps, node and material index — for callers that instance a model's geometry themselves through `DrawInstanced` |
| `Bounds()`, `Height()` | world-space AABB in the current pose; the vertical extent (FBX rigs are usually centimetres) |
| `JointWorld(name)`, `JointBySuffix(suffix)`, `JointNames()` | a joint's model-space matrix in the last pose — the anchor for attaching a weapon to a hand |
| `Instance(r)` | an independently posable copy sharing meshes, textures and skin buffers; only the hierarchy and palettes are per instance |
| `Release()` | |

`examples/model` loads `build/assets/Duck.glb` (or `-file`) and spins it
over a ground slab; `scripts/fetch-assets.sh` fetches the Khronos Duck and
BoxTextured samples, the Poly Haven textures and `CesiumMan.glb`. The
glTF samples were not present in `build/` at the time of writing, so run
the script before the model, skinned and materials examples.

## Models: FBX

`render/fbx` is a pure-Go reader for **binary** FBX (ASCII FBX is not
supported) that converts to the same `gltf.Document`, so everything
downstream is shared:

```go
d, err := fbx.Parse(data)                                  // *fbx.Doc: version + node tree
doc, err := fbx.ToGLTF(d, func(uri string) ([]byte, error) { // external textures, tried relative/absolute/basename
    return os.ReadFile(filepath.Join(dir, filepath.FromSlash(uri)))
})
```

`ToGLTF` handles the 6100 (name-keyed) and 7700 (id-keyed) generations,
splits a mesh into primitives per material, extracts skins (joint list
plus inverse-bind matrices), converts every `AnimationStack` to a clip
(Euler-degree rotation curves sampled on the union of key times and turned
into quaternions), and maps Phong materials to a PBR subset: diffuse
colour and texture (embedded `Content` or the resolve callback), shininess
to roughness.

Mixamo-style exports ship the character and each clip as separate FBX
files on differently namespaced rigs (`mixamorig:Hips` against
`mixamorig6:Hips`). `fbx.Retarget(dst, src)` rewrites `src`'s animation
channels to drive `dst`'s nodes by namespace-stripped bone name. It is not
an index remap: each key is converted into a rest-relative delta and
re-expressed against the destination's rest pose, so a bone the two
exporters decompose differently still lands right, and a rest frame
reproduces the character's own bind pose. Run it before the clip is
played, while `dst` still holds its bind pose, and channels whose bone has
no match are dropped.

```go
meshDoc, _ := loadFBX(*meshPath)
animDoc, _ := loadFBX(*animPath)
fbx.Retarget(meshDoc, animDoc)
model, _ := r3.BuildModel(meshDoc)
player := render.NewAnimationPlayer(model, animDoc.Animations)
```

`examples/actor` is that sequence with `-mesh` and `-anim` flags, scaling
the model to 1.8 units from `Bounds()`; `examples/actorblend` loads five
clips from an asset root (`-assets`, default `build/actors`), retargets
each, and crossfades between them on keys 1–5. The FBX tests
(`render/fbx`, `render/gpuskin_test.go`, `render/skin_test.go`) read a
Mixamo rig from the directory named by `GFX_FBX_ASSETS`
(`models/hostile.fbx` and `animations/*.fbx` under it) and skip when it is
unset. No FBX sample ships with the repository.

## Animation and skinning

`render.AnimationPlayer` is the Godot-shaped clip player with crossfades:

```go
player := render.NewAnimationPlayer(model, doc.Animations)
player.Play("Idle", render.PlayOpts{Loop: true})
player.Play("Firing Rifle", render.PlayOpts{Fade: 0.15})   // on a state change
player.Advance(dt)                                         // per frame, before model.Draw
```

| Call | Meaning |
|------|---------|
| `Play(name, opts...)`, `PlayIndex(i, opts...)` | start a clip; `PlayOpts{Loop, Fade, Speed}`; with no options the player's `Loop` flag applies and the clip restarts at 0 |
| `Advance(dt)`, `Seek(t)` | advance (a looping clip wraps, a non-looping one clamps, stops and fires `OnFinished`); jump to a time |
| `Stop()`, `Resume()` | freeze the current pose (a downed actor stays down); continue |
| `Clips()`, `Current()`, `Playing()`, `IsPlaying()`, `Finished()`, `Fading()`, `Position()`, `Duration()`, `Speed()`, `SetSpeed(s)` | state |
| `OnFinished`, `SetClipCallbacks(finished, looped)` | lifecycle hooks |

While a fade runs both clips are sampled into their own `gltf.Pose`
buffers from the model's rest pose and mixed per joint (translation and
scale lerp, rotation short-arc slerp) before being written to the
hierarchy; the buffers are reused, so a blended frame allocates nothing.
The sampling primitives are public in `gltf`: `Animation.SampleInto(t,
pose)`, `NewPose(nodes)`, `Pose.Reset`, `BlendPose(dst, a, b, w)`,
`Pose.Write(nodes)`, and the simpler `Animation.Apply(t, nodes)`.

Skinning is in the vertex shader by default (`render/gpuskin.go`): the
bind-pose vertex buffer uploads once, per-vertex joints (`uint16x4`) and
weights (`float32x4`) sit in a second vertex slot, and the only per-frame
traffic is the joint palette (`array<mat4x4f>`, 64 bytes per joint, in its
own bind group, written when the pose moves). Both shader families and the
shadow pass have skinned pipeline variants, built lazily. The CPU skinner
(`render/skin.go`) remains the reference implementation and the fallback:
set `render.GPUSkinning = false` before building models, or
`GFX_CPU_SKIN=1` in the environment, and both paths render the same pixels.
A model reads the switch on its first draw and keeps that answer.

Bone attachment reads the posed joint after `Advance`:

```go
if hand, ok := actor.JointBySuffix("RightHand"); ok {
    rifle.Draw(r3, place.Mul(hand).Mul(attach))
}
```

`examples/skinned` plays CesiumMan's walk clip (`-screenshot` seeks to
0.6 s for a mid-stride pose).

## Picking

Picking is a ray test against the retained draw list of the current frame
(the draws queued since the last `Begin`; they stay valid after `Render`,
so input handling can pick against what was just shown):

```go
r3.SetPickTag(partID)          // stamps every subsequent draw; Begin resets it to -1
r3.DrawPBR(mesh, model, color, 0.1, 0.5, nil)

origin, dir, ok := render.ScreenRay(viewProj, x, y, float32(w), float32(h))   // viewport-relative pixel -> world ray
hit, ok := r3.Pick(origin, dir)                                                 // PickHit{Index, Tag, T, Point}
hit, ok = r3.PickWhere(origin, dir, func(tag int) bool { return tag != ghosted })
```

The ray is carried into each draw's model space, tested against the
mesh's AABB and then its triangles (Möller–Trumbore, both-sided, shared
with physics through `core.RayAABB`/`core.RayTriangle`), and the nearest
world-space hit wins. `PickWhere` restricts the test to draws whose tag
passes `keep`, so context geometry drawn ghosted does not hide what is
behind it. Material draws are pickable too, but only an instanced draw's
first transform is tested, and skinned geometry is tested in its bind
pose on both skinning paths. `examples/partviewer` and
`examples/viewport3d` resolve clicks this way.

## The scene tree

`scene.Tree` is DESIGN.md §4.1 in its minimal form: nodes are
`ecs.Entity` handles (`scene.Node`), their transforms live in one
contiguous `Transform` column, parent and depth in another, and
`Update()` propagates world matrices in one pass per depth level over the
column rather than by recursive walk.

```go
tree := scene.NewTree()
parent := tree.Spawn(scene.Node{})                    // zero Node = root
child := tree.Spawn(parent)
tree.SetLocal(child, core.V3(2.2, 0, 0), core.QuatIdentity(), core.V3(0.5, 0.5, 0.5))
tree.Local(child).Rot = core.QuatAxisAngle(core.V3(1, 0, 0), t)   // in-place mutation
tree.Update()
r.Draw(cube, tree.WorldMatrix(child), color)
```

`Transform` is `{Pos core.Vec3; Rot core.Quat; Scale core.Vec3}` plus a
cached world matrix; `tree.World` is the underlying `*ecs.World`. The
propagation pass rescans the full column per depth level instead of
walking dirty subtrees, and typed node kinds, names, child order,
lifecycle callbacks and signals are not built. `examples/cubes` composes
its orbiting cubes with it.

## Physics: physics/p3

`physics/p3` is a pure-Go 3D physics engine built in the order its
consumers needed it (`physics/PLAN.md`): collision queries over a static
world first, then a kinematic character controller, then rigid-body
dynamics. Bodies live in flat slices addressed by generation handles
(`BodyID`, `NilBody`) with a world AABB BVH for queries; every query takes
a `Layer` bitmask (`LayerAll` matches everything).

Shapes are a tagged union built by constructors: `Sphere(r)`,
`Capsule(r, halfHeight)` (along local Y), `Box(half)`, `Mesh(*TriMesh)`
(static triangle soup from `NewTriMesh(verts, idx)`) and `Hull(*ConvexHull)`
(quickhull via `NewConvexHull(points)`; query and static use only).

| World method | Meaning |
|--------------|---------|
| `AddBody(shape, pos, rot, layer)`, `AddTrigger(…)`, `RemoveBody(id)` | static and kinematic bodies; a trigger is an overlap-only volume invisible to solid queries |
| `SetPose(id, pos, rot)`, `Pose(id)` | move a body (the BVH rebuilds on mutation) |
| `RayCast(origin, dir, maxDist, mask)` | nearest surface along a normalised direction; `Hit{Body, T, Point, Normal}` |
| `ClosestPoint(p, maxDist, mask)` | nearest surface point |
| `OverlapSphere(center, r, mask, visit)`, `OverlapCapsule(a, b, r, mask, visit)`, `OverlapTriggers(…)` | overlap callbacks |
| `CastSphere(origin, r, dir, maxDist, mask)`, `CastCapsule(a, b, r, dir, maxDist, mask)` | swept shapes |
| `AddDynamicBody(shape, pos, rot, mass, mat, layer)`, `SetGravity(g)`, `Step(dt)` | rigid dynamics (v1: sphere and box shapes); `Material{Restitution, Friction}`, `DefaultMaterial` |
| `Velocity(id)`, `SetVelocity(id, v)`, `ApplyImpulse(id, imp)`, `Asleep(id)` | per-body dynamics |

Queries allocate nothing (`TestQueryAllocs`) and run at about 1 µs per ray
on a 400-body scene. The solver is sequential impulses with warm starting
and a split-impulse position pass, island sleeping, and a specialised
narrowphase (no GJK/EPA yet, so dynamic capsules and hulls wait); it is
deterministic for the same binary. Joints, 2D and debug drawing are not
built.

The kinematic character is Godot's `move_and_slide` shape:

```go
char := p3.NewCharacter(world, core.V3(0, 0.9, 0), 0.35, 0.55)   // capsule centre, radius, half-height
vel.Y = p.vel.Y + gravity*dt
if char.OnGround { vel.Y = gravity * dt; if jump { vel.Y = jumpVel } }
p.vel = char.MoveAndSlide(vel, dt)         // sweeps, slides (<= 4 planes), steps up, snaps to ground; returns the unblocked velocity
p.triggers.Update(char, p3.LayerAll, onEnter, onExit)   // p3.TriggerEvents: enter/exit callbacks
```

`Character` exposes `MaxSlopeDeg` (46), `StepHeight` (0.35), `SnapLen`
(0.25), `OnGround`, `GroundNormal` and `Ground` (a kinematic platform the
controller stands on is carried). `examples/fps` walks a level declared in
`level.gml` — `script/gml`'s `LoadSceneFile` builds the solids, their
colliders and triggers into one `p3.World` (`SceneView.World()`,
`SceneView.Body(id)`) and draws them through `Renderer3D` — with a
staircase, a ramp, a moving platform and a pressure-plate door.

## 3D inside the UI, and 3D with the UI

There are two ways to put a 3D frame on screen with the 2D toolkit.

**Compositing** draws the 3D frame first and the UI over it in the same
command encoder: the 3D pass clears the target, the UI pass loads it.
`examples/partviewer` does this for a full-window part with a floating
tool rail and properties panel:

```go
r3.Begin(vp, lightDir, eye)
drawPart(r3)
enc := device.CreateCommandEncoder()
r3.Render(enc, view, depthView, gpu.Color{R: 0.075, G: 0.08, B: 0.10, A: 1})
r2.Begin(w, h)
u.Frame(float32(w), float32(h))
pass := enc.BeginRenderPassLoad(view)   // keep the 3D pixels
r2.Flush(pass)
pass.End()
queue.Submit(enc.Finish())
```

**Embedding** renders the 3D frame into an offscreen `render.View3D` (a
private colour and depth texture pair) and places it in the layout as the
`ui.Viewport3D` element, which sizes the target to its laid-out box and
paints it like any image — so the scene clips, scrolls and stacks with
other widgets and several viewports can coexist (one `Renderer3D` serves
one `View3D` per submission). `examples/viewport3d` embeds a pickable
scene between a header, a side panel and a footer:

```go
view3d := render.NewView3D(device, r2, format)   // same format the Renderer3D was built for
vpEl := ui.Viewport3D(view3d).Grow().OnTap(func(x, y float32) {   // viewport-local pixels
    vw, vh := view3d.Size()
    vp, _ := cam.ViewProj(vw, vh)
    if o, d, ok := render.ScreenRay(vp, x, y, float32(vw), float32(vh)); ok {
        if hit, ok := r3.Pick(o, d); ok && hit.Tag >= 0 { selected.Set(hit.Tag) }
    }
})
u := ui.New(r2, font, func() ui.Element {
    return ui.Div().Row().Grow().Gap(12).Children(vpEl, sidePanel)
})

// per frame: layout first (it sizes the target), then the 3D pass into it, then the UI pass that samples it
u.Layout(float32(w), float32(h))
vw, vh := view3d.Size()
vp, eye := cam.ViewProj(vw, vh)
r3.Begin(vp, lightDir, eye)
drawScene(r3)
enc := device.CreateCommandEncoder()
view3d.Render(enc, r3)
r2.Begin(w, h)
u.Frame(float32(w), float32(h))
pass := enc.BeginRenderPass(target, clear)
r2.Flush(pass)
pass.End()
queue.Submit(enc.Finish())
```

`Viewport3DEl` has `Size(w, h)` (default 320x240), `Grow()`, `OnTap`,
`Overlay(func(*render.Renderer2D, ui.Rect))` for anti-aliased 2D vector
graphics painted over the frame (grids, snap markers), and `Rect()` so
orbit-camera code can route only the pointer events that land inside the
viewport. `View3D.Clear` is the viewport background.

## Running the examples

All of these live in the `examples` module. Native runs need
`scripts/fetch-wgpu.sh` (the library lands in `build/wgpu/`,
`GFX_WGPU_LIB` overrides); `scripts/fetch-assets.sh` fetches the Duck and
BoxTextured glTF samples, the Poly Haven textures and CesiumMan into
`build/`. Every 3D example has a `-screenshot out.png` flag that renders
one frame without a window and a `-frames N` flag that exits after N
frames.

| Example | Shows |
|---------|-------|
| `cubes` | scene tree, legacy draws, shadows |
| `model` | glTF loading (`-file` for any asset) |
| `skinned` | CesiumMan with the AnimationPlayer and GPU skinning |
| `materials` | PBR texture sets, hex tiling, triplanar, point lights, fog, instancing |
| `actor` | binary FBX with a separately shipped clip, `fbx.Retarget` (`-mesh`, `-anim`) |
| `actorblend` | five clips crossfaded, bone attachment, tint and fade (`-assets`) |
| `fps` | the kinematic character in a gml-declared level with triggers |
| `partviewer` | 3D under a 2D UI in one frame, click picking with tags |
| `viewport3d` | `ui.Viewport3D` inside a layout, picking from the element's tap |
